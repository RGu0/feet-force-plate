# RAY-119 工程师角色检修接线设计

## 目标

让已通过 Platform IAM 独立登录并具有 `PLATFORM_ENGINEER` 角色的工程师，
在机构筛查工作台中访问只读工程检修功能。工程师可以人工添加或选择设备资产
ID，随后查看该 ID 对应的动态坏点分布。该流程不以 CH340 USB 序列号、串口
路径、VID/PID 或 USB 位置为设备身份来源。

## 边界

- 机构登录仍只用于筛查、License 和终端访问；它不授予工程检修权限。
- 工程检修每次从入口发起独立 Platform IAM 登录，请求现有
  `POST /v1/platform/login`。
- 客户端只在内存中保存成功响应的短期访问令牌、角色和过期时间；绝不写入
  密码、令牌、原始帧、串口路径或 USB 描述符。
- 仅 `PLATFORM_ENGINEER` 角色且令牌仍有效的会话可以创建工程检修服务。
  缺少该角色、网络/协议失败或令牌过期均按拒绝处理。
- 工程检修保持只读：它只能登记/选择资产 ID 并展示掩码摘要、格点标记和
  健康状态，不能编辑掩码、读取原始帧或改变采集/算法输入。

## 架构

新增一个客户端 Platform 工程师认证适配器。它复用现有访问服务地址和 TLS
验证配置，用 `PlatformLoginRequest` 调用 `/v1/platform/login`，并验证
`PlatformLoginResponse` 中存在 `PLATFORM_ENGINEER` 与未过期的时间戳。

工作台的“设备与支持”页保留工程检修入口。点击后首先显示工程师登录对话框；
登录成功后，在本次短期会话内构造 `EngineeringMaintenanceService`。服务的
原本地确认回调改为会话授权器：每次登记资产 ID 或读取分布时重新检查角色和
过期时间。过期后关闭检修对话框并要求再次登录。

工程师登录与机构会话彼此独立。工程师登录成功不改变机构账户、License、
硬件启动门禁或筛查流程；退出应用时仅丢弃内存中的工程师会话。

## 数据与错误处理

- 手工资产 ID 继续由 `EngineeringDeviceBindingStore` 原子保存，只包含所选 ID
  与已知 ID 列表。
- 动态掩码和脱敏硬件健康审计仍按该人工资产 ID 分区。
- 登录失败、角色不足、过期与网络故障显示通用工程访问不可用信息；不得显示
  密码、令牌、HTTP 响应、串口或原始帧。
- 工程检修入口只在正式工作台已创建时可用；未获得工程师授权时不创建服务或
  暴露掩码内容。

## 验证

自动测试覆盖：正确请求与响应解析、工程师角色允许、非工程师角色拒绝、过期
令牌拒绝、密码/令牌不进入持久化注册表、手工资产 ID 的选择保持，以及授权
失效后的读写拒绝。

真机验收在 COM6 上完成：工程师登录，人工登记/选择 `FFP-001`，关闭并重开
检修界面确认选择保持；断开并重新连接 CH340 后再次工程师登录，确认仍恢复
`FFP-001` 并只显示该 ID 的只读坏点分布。验收只记录脱敏汇总，不保留原始帧。
