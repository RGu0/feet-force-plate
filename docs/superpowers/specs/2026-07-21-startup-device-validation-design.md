# 软件启动设备初始化与 5 秒空载校验设计

## 1. 目标

机构端软件每次启动后必须先完成设备初始化校验。系统确认 DO-P4864 已连接、能够持续输出数据，并完成一次连续 5 秒的空载传感器基线采集后，才允许进入工作台和开始正式筛查。

此功能用于开机自检、零点基线观察和异常传感器识别，不等同于工厂标定，也不在标定资料尚未确认时自动写入传感器校准系数。

## 2. 产品原则

- 每次软件启动强制执行，不提供普通操作员跳过入口。
- 校验期间设备表面必须无人踩踏、无外物。
- 以主机单调时间连续采集 5 秒，不把固定帧数当作 5 秒。
- 采集链路、显示和日志相互隔离；网络不可用不应阻止本地设备校验。
- 客户界面只显示通俗结论和一个主要恢复动作；详细原因进入脱敏内部日志。
- 未通过校验时不得进入正式检测，但可以重新连接或重新校验。

## 3. 页面流程

页面采用单页进度流程，默认依次显示：

1. 正在初始化软件环境；
2. 正在连接压力设备；
3. 请保持设备表面空载；
4. 正在采集基线数据，显示 5 秒倒计时；
5. 正在分析传感器状态；
6. 校验通过，自动进入工作台；或显示需要处理的单一恢复动作。

进度条必须反映实际状态，不使用纯动画伪造进度。连接阶段为不确定进度；进入 5 秒采集后按单调时间展示确定进度。页面同时显示当前步骤、简短说明和必要的取消/退出入口。

## 4. 状态机

启动校验状态定义为：

`BOOTSTRAPPING -> CONNECTING -> WAITING_FOR_EMPTY -> COLLECTING_BASELINE -> VALIDATING -> PASSED`

失败状态包括：

- `DEVICE_NOT_FOUND`：未发现设备；主要动作“重新连接”；
- `DEVICE_BUSY`：串口被占用；主要动作“关闭占用程序后重试”；
- `LOAD_NOT_EMPTY`：检测到明显载荷；主要动作“清空设备”；
- `STREAM_INTERRUPTED`：5 秒内数据中断；主要动作“重新校验”；
- `SIGNAL_INVALID`：传感器数据未通过基线规则；主要动作“重新校验”，重复失败后提示联系支持；
- `INTERNAL_ERROR`：非预期错误；主要动作“重新启动”，同时生成内部诊断编号。

校验失败后不得沿用部分数据。每次重试必须新建一次校验运行记录，并重新采集完整连续 5 秒。

## 5. 数据采集契约

- 复用正式采集使用的 `ByteTransport`、协议解析器和原始帧契约，不建立旁路解码器。
- 设备连接成功并获得结构有效的原始帧后才开始计时。
- 使用 `host_monotonic_ns` 判断连续 5 秒窗口，保存开始时间、结束时间、成功帧数、无效候选、重同步次数和最大主机接收间隔。
- 当前真机输入按已验证的 48×64 `uint8` 原始阵列处理；若协议版本变化，校验运行必须记录协议和数据模式版本。
- 空载校验数据默认只保留必要的统计摘要；原始帧是否保留遵循内部诊断和数据保留策略，不进入客户报告。
- 网络上传不是本地校验成功的前置条件；校验摘要和故障日志可进入既有自动补传队列。

## 6. 首版校验规则

首版只输出 `PASS`、`RETRYABLE_FAIL` 或 `SERVICE_REQUIRED`，不输出医疗结论。

校验至少覆盖：

- 5 秒窗口内存在持续有效数据；
- 设备未断开，协议解析未进入不可恢复错误；
- 实际接收速率和最大间隔未超出版本化硬件基线；
- 空载总响应未表现为明显有人踩踏或有外物；
- 大面积固定值、持续饱和、完全无变化等明显异常；
- 单点或局部异常、噪声和漂移超过版本化阈值；
- 规则版本、阈值版本和结果原因码可审计。

在供应商标定资料、物理单位和长期漂移范围确认前，阈值只能基于原始计数和经真机验证的统计范围，不得把结果描述成力值、压力值或正式校准结果。

## 7. 结果和持久化

每次启动产生一个内部 `DeviceValidationRun`，至少包含：

- `validation_run_id`、终端标识、设备/端口信息；
- 软件、协议、数据模式和规则版本；
- 开始、结束时间和最终状态；
- 5 秒窗口统计和失败原因码；
- 重试次数、前一次运行引用；
- 内部日志关联 ID。

客户页面不展示坏点明细、质量阈值、协议错误或原始曲线。内部支持工具可以在权限控制下读取这些内容。

## 8. 与现有模块的关系

- RAY-78 提供真实硬件基线、原始值语义和后续标定依据；
- RAY-80 提供设备连接和正式采集共用的数据通道；
- RAY-101/P-05 承载启动页面和一键流程状态机；
- RAY-86 承载可靠性与异常注入验收；
- RAY-103 承载内部故障日志和支持诊断。

## 9. 验收边界

自动测试至少覆盖：正常通过、无设备、端口占用、空载条件不满足、中途断线、帧率异常、固定值、饱和、异常噪声、重复失败和重试成功。

真机验收至少覆盖：

- 连续多次冷启动均能完成完整 5 秒采集；
- 校验期间施加载荷能够阻止通过，清空后可重新开始；
- 拔线和重新连接不会误用旧数据；
- 校验通过后才进入工作台；
- Windows 目标设备上的进度、倒计时、键盘焦点和提示文字可用；
- 每项结论均在 `docs/evidence/linear/<ISSUE-ID>/` 留下可复现证据。

缺少真机、Windows 或人工验证时，对应 Linear issue 只能进入 `In Review`，不能标记 `Done`。

## 10. Linear 拆分

1. **5 秒空载数据采集与传感器基线校验**：底层采集契约、规则、结果模型和自动测试；
2. **启动设备初始化状态机与进度页面**：启动编排、空载提示、倒计时、结果和恢复操作；
3. **启动校验失败恢复、日志与验收证据**：异常注入、真机/人工验收、内部日志和本地 evidence。

三个任务均作为 RAY-101 的子任务；底层校验先于页面集成，验收任务依赖前两项完成。
