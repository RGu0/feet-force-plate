# UI 实机全流程设计

## 目标

在现有 Qt 机构端界面中，使用已连接的 DO-P4864 与 `aliyun-agentic` 联调服务，
由操作员实际完成首次激活、登录、设备启动校验、受试者与授权、四段静态站立、
实时热图、基础报告预览和 PDF 导出。界面操作是流程唯一的驱动；命令行脚本不再
充当演示应用。

## 范围与边界

- 服务端使用当前 `https://39.105.216.113:7443` 联调入口。客户端必须明确显示
  “联调环境”，并使用已固定的 CA 证书与 License 公钥；不得将该入口称作生产。
- 首次激活使用服务端已创建且配对的资产编号/一次性激活码。它们仅由操作员在
  P-00 界面输入，绝不进入日志、测试工件、证据文档或源码。
- 设备资产编号是业务身份；CH340 端口、VID/PID、USB 位置和缺失的 USB serial
  只能用于发现连接，不能用于授权绑定。
- 当前 MVP 只生成非诊断 BASIC 报告：相对热图与左右相对负重。不得显示绝对力、
  COP、稳定性评分、风险分级或疾病结论。
- 当前云端会话摄取尚未与该 UI 组合根完成实机验证。会话完成后如无真实上传确认，
  UI 只能显示“待同步”，不得显示“已上传”。

## 操作员可见流程

1. **P-00 首次激活。** 应用读取联调配置、显示“联调环境”，显示检测到的压力板
   状态。操作员输入机构名称、账号、资产编号、激活码和密码；服务端成功返回后
   进入已登录状态。
2. **登录与启动门。** 后续启动可在同一界面登录。每次登录后先运行现有启动校验：
   实体板连接、连续有效信号和空载基线通过后才能进入工作台。
3. **受试者、档案与必要授权。** 使用现有匿名建档/机构编号和授权页面。界面只有
   在授权确认后开放新检测。
4. **P-05 检测前检查。** 点击“开始新检测”后，应用先请求真实 HardwareLease，
   再检查本地存储和硬件运行条件。租约冲突、网络错误、设备断开和空间不足均在
   当前页面显示可操作错误，不创建正式会话。
5. **四段实机采集。** 现有站位页对每一段显示动作和稳定倒计时；操作员点击
   “开始本段”后，实时采集页显示硬件最新帧、热图、相对负重和 20 秒倒计时。
   四段顺序为并足睁眼、并足闭眼、左脚在前半串联、右脚在前半串联。停止按钮、
   断线、存储错误或安全中止会令本次会话无效且不生成报告。
6. **提交、结果与报告。** 最后一段结束时 UI 进入“正在完成本地保存”，等待硬件
   质量门、加密会话提交、公开物理合同和本地相对分析全部成功。仅在这些步骤完成
   后才进入既有结果页、报告预览、导出/打印操作。

## 架构

### 1. 真实运行时组合

新增一个 `LiveInstitutionScreeningRuntime` 组合根，供
`client.app.packaged_entry` 的默认工作台工厂使用。它拥有：

- 配置好的 `ClientAccessRuntime` 和当前已认证会话；
- 受 Keychain 保护的本地数据密钥、`StateStore`、加密会话目录和恢复扫描；
- `SerialByteTransport`、`DaoOneP4864Parser`、启动门产出的空载基线、
  `DoP4864HardwareQualityGate`；
- 现有 `ScreeningCoordinator`、`ReportConnectedController`、
  `ScreeningWindow`、`PhysicalGridOverlay` 和 `LiveDisplayProjection`；
- 生命周期受控的 HardwareLease 客户端，检测开始前获取、进行中续租、成功/失败/退出
  均释放。

默认包入口不再以裸 `ScreeningWindow()` 作为工作台。回放入口仍保持显式 `--replay`，
不与实机运行时共用数据源。

### 2. UI 与实机采集的协议

新增 `QtLiveHardwareAcquisition` 适配器，实现现有 `AcquisitionPort` 及阶段扩展：

- 第一段开始时创建一个 session、打开串口读线程、创建加密 stager，并持续采集至
  第四段结束；不把四段拆成四个独立硬件会话。
- UI 的每次“开始本段”只推进同一采集会话的阶段边界和当前动作提示；Qt 定时器驱动
  `ApplicationController.on_acquisition_elapsed()`，确保倒计时和页面状态来自同一
  操作员动作。
- 最新原始帧同时写入 durable stager 与显示 mailbox；显示层只取最新帧，不能阻塞
  存储。
- 第四段的 UI 倒计时归零后进入 finalizing，而不是立即报告成功；适配器在后台完成
  硬件质量、提交和公开物理会话恢复后，回到 Qt 主线程通知 coordinator。
- 任何中止、掉线、质量失败或提交失败都会停止读线程、删除暂存数据、释放租约，并在
  UI 提供“重新检测”。

### 3. 本地物理报告与会话状态

在提交成功后，运行时调用 `process_committed_physical_session()`，使用由 UI 阶段
记录生成的 `StaticBalanceProtocolContext`。仅所有阶段明确完成且无中止时，
`BASIC_READY` 可以进入报告页。报告文档交给现有 `ReportConnectedController`，
由现有页面提供预览、PDF 导出与打印。

本地数据库的会话状态、报告索引和读模型由一个适配器统一维护，不能再使用
`LocalReplayStore` 或 fixture 的 `V1ReplayDebugProcessor`。恢复扫描只处理已经
提交的有效会话；未完成采集绝不恢复为可报告会话。

### 4. HardwareLease

`ClientAccessRuntime` 增加显式、可测试的 lease 生命周期接口。开始新检测前以已认证
令牌调用真实 `/v1/access/hardware-lease`；lease 绑定当前 account、License、资产和
client installation。运行中按 TTL 续租，结束或异常后释放。lease 续租失败不删除
本地已采集数据，但禁止开始下一项检测，并在 UI 显示待恢复状态。

### 5. 联调配置与信任材料

提供一个不含秘密的本机联调配置安装步骤：从服务器取得公开 CA 证书和公开 License
验证键，校验其指纹/键 ID 后，写入受限权限的应用配置目录。配置仅包含 base URL、
CA 文件路径、公开键路径、键 ID 和 `integration_mode=1`；激活码、账号密码、refresh
token、私钥、数据库 DSN 均不写入该配置。

## 故障处理

| 场景 | UI 行为 | 数据与授权行为 |
| --- | --- | --- |
| 首次激活失败 | 留在 P-00，显示泛化错误 | 不回显激活码或密码 |
| 启动校验失败 | 留在设备检查，可重新检查 | 不进入工作台 |
| Lease 冲突或网络失败 | 留在预检，可重试 | 不创建会话 |
| 采集期间断线/停止/安全中止 | 显示本次未完成 | 删除暂存，不出报告，释放 lease |
| 质量或加密提交失败 | 显示重新检测 | 不创建有效会话/报告 |
| 本地分析不可发布 | 显示重新检测 | 保留合法已提交会话，抑制报告 |
| 上传未证实 | 结果页显示待同步 | 不显示上传成功 |

## 验证策略

- 单元测试：lease 生命周期、阶段状态机/Qt 定时、串口适配器的成功/中止/掉线/质量失败、
  本地报告门控、配置拒绝秘密或非 HTTPS。
- Qt 集成测试：从 P-00 激活成功到四段页面状态、实时帧、finalizing、结果/报告预览；
  使用受控传输与内存服务替身，仅验证 UI 协议。
- 联调实测：操作员在 UI 中输入真实联调库存凭据，完成启动门、获得真实 lease、
  通过 UI 执行四段采集并生成匿名 BASIC 报告。证据只保存脱敏结果、时间、帧统计、
  lease 成功/释放状态和 UI 截图，不保存凭据、原始矩阵或报告内容。
- 回归：默认入口、显式 replay、现有访问/启动门/物理本地分析/上传队列测试均须通过。

## 非目标

- 不把当前 `:7443` 联调环境升级为生产域名、公有 CA 或 443。
- 不创建客户可见的诊断、风险预测、临床评分或云端完整报告。
- 不用脚本自动填写 UI 表单、自动确认动作完成，或以回放代替实机证据。
- 不把 USB 元数据绑定为业务资产身份。
