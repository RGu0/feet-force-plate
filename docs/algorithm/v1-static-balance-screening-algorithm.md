# V1 静态平衡筛查算法设计

| 项目 | 内容 |
|---|---|
| 协议 ID | `static-balance-fall-screen` |
| 协议版本 | `1.0` |
| 算法集版本 | `fall-screen-rule-set/1.0` |
| 指标管线版本 | `static-balance-feature-pipeline/1.0` |
| 标准输入版本 | `physical-pressure-session/1.0` |
| 适用人群 | 60 岁及以上 |
| 产品用途 | 机构端初步筛查和进一步评估提示 |
| 非用途 | 医疗诊断、治疗建议、处方建议、未来跌倒概率预测 |
| 设计日期 | 2026-07-21 |

## 1. 设计结论

V1 采用“背景风险优先、动作完成参与判断、压力指标补充和发现隐匿风险”的分层规则模型，不采用固定百分比权重相加。

算法按以下顺序执行：

```text
前置信息与当日安全检查
  → 四阶段动作测试和完成情况记录
  → 数据质量门控
  → 标准物理力场的 ML/AP 压力中心轨迹与静态指标
  → 背景风险等级 / 完成程度等级 / 压力指标等级
  → 取三者中的最高风险等级
  → 在对应等级区间内生成 0–100 综合筛查评分
  → 输出报告与进一步评估建议
```

风险与评分方向：

| 综合风险 | 综合筛查评分 | 解释 |
|---|---:|---|
| 低风险 | 80–100 | 本次筛查未发现明显高风险依据；不代表未来不会跌倒 |
| 中风险 | 60–79 | 存在需要关注的背景因素、动作完成问题或平衡指标异常 |
| 高风险 | 0–59 | 存在明确高风险背景、明显动作失败或显著平衡异常 |
| 无法评价 | 不给分 | 技术或协议原因导致证据不足，且没有可独立成立的中/高风险规则 |

算法先定风险等级，再给分。高风险事实一旦成立，最终分数不得超过 59；中风险事实一旦成立，最终分数不得超过 79。

## 2. 适用范围与能力门控

### 2.1 年龄

- `age_years >= 60`：允许进入 V1 综合跌倒风险分级。
- `age_years < 60`：可以完成静态平衡测试和获得分项结果，但不使用本算法输出低/中/高老年人跌倒风险。
- 年龄未知：允许保存测试，但不输出基于 60 岁以上参考范围的综合评分。

### 2.2 标准物理输入

核心算法不直接接收设备原始阵列，而只接收 [`physical-pressure-session/1.0`](standard-physical-input-contract.md)：

- 每个感应点具有稳定 `cell_id`、身体坐标 `ml_mm / ap_mm` 和有效面积 `active_area_mm2`；
- 每帧提供每点真实法向力 `normal_force_n`；
- 每帧提供严格递增的实际单调时间 `timestamp_s`；
- 坐标统一为身体坐标：向受试者右侧为 ML 正方向，向受试者前方为 AP 正方向；
- 输入声明物理、时间、坐标和测量不确定度的验证状态与版本。

点数、点尺寸、点间距、阵列形状、设备型号、原始值类型、内存顺序、通信协议和设备专用标定均属于硬件层。硬件层完成原始数据到 N、mm、mm²、s 的真实物理换算后，才可以交给本算法。

算法按标准能力字段声明最低采样率、所需时长、输入模式版本、测量一致性规范、参考人群版本和验证状态，不按设备型号写分支。未满足能力条件时返回 `UNSUPPORTED`、`DEGRADED` 或 `INVALID`，不得静默生成正式结果。

## 3. 前置信息

### 3.1 必选的最小信息

以下字段必须做出明确选择；`UNKNOWN` 和 `DECLINED` 不能转换为“否”：

| 字段 | 选项/结构 | 用途 |
|---|---|---|
| 年龄 | 年龄或年龄段 | 适用范围和参考分层 |
| 过去 12 个月跌倒次数 | `0 / 1 / >=2 / UNKNOWN` | 临床高风险锚点 |
| 跌倒是否造成受伤或就医 | `YES / NO / UNKNOWN / NOT_APPLICABLE` | 严重跌倒识别 |
| 跌倒后是否长时间无法自行起身 | `YES / NO / UNKNOWN / NOT_APPLICABLE` | 严重跌倒识别 |
| 是否发生意识丧失、晕厥或近乎晕厥 | `YES / NO / UNKNOWN` | 高风险背景和转诊提示 |
| 最近是否反复头晕 | `YES / NO / UNKNOWN` | 背景风险 |
| 头晕是否影响站立/行走或常在起身后出现 | `YES / NO / UNKNOWN / NOT_APPLICABLE` | 高风险背景 |
| 是否感觉站立或行走不稳 | `YES / NO / UNKNOWN` | 一般背景风险 |
| 是否担心跌倒 | `YES / NO / UNKNOWN` | 一般背景风险 |
| 是否使用/被建议使用助行器，或经常扶家具 | `YES / NO / UNKNOWN` | 一般背景风险 |

### 3.2 可选药物风险标签

不采集药名、剂量、频次、处方照片或手工文本。操作员或受试者可以选择一个或多个标签，也可以不提供：

核心标签：

- `SLEEP_SEDATIVE_ANXIOLYTIC`：助眠、镇静或抗焦虑类；
- `MOOD_PSYCHIATRIC`：调节情绪或精神状态类；
- `STRONG_ANALGESIC`：强效止痛类；
- `ANTIEPILEPTIC`：抗癫痫或防抽搐类。

条件性标签：

- `BP_LOWERING_OR_DIURETIC`：可能引起血压降低或排尿增加的药物；
- `SEDATING_ALLERGY_MOTION_MUSCLE`：容易引起困倦的抗过敏、晕车或肌肉放松类药物。

药物标签整体状态：

```text
PROVIDED / NONE_REPORTED / UNKNOWN / DECLINED / NOT_COLLECTED
```

药物标签不单独触发高风险，不建议自行停药。核心标签作为一般背景因素；条件性标签只有在同时存在头晕、站起后发晕、困倦或反应迟缓时进入风险规则。

### 3.3 当日安全门控

测试开始前询问并观察：

- 当前是否明显头晕或近乎晕厥；
- 是否有胸部不适、急性呼吸困难或无法安全站立；
- 操作员是否能够在受试者旁近距离保护；
- 周围是否有可用的安全扶手或保护条件。

当前出现明显头晕、近乎晕厥、胸部不适或无法安全站立时，不开始测试。该结果不是技术失败：如果高风险背景已经成立，可以输出高风险提示，但压力板分项标记为“未进行”。

## 4. 标准动作协议

### 4.1 四个阶段

| 顺序 | 阶段 ID | 姿势 | 视觉 | 有效采集时间 |
|---:|---|---|---|---:|
| 1 | `BILATERAL_EYES_OPEN` | 正站，双脚并拢 | 睁眼 | 20 秒 |
| 2 | `BILATERAL_EYES_CLOSED` | 正站，双脚并拢 | 闭眼 | 20 秒 |
| 3 | `SEMI_TANDEM_LEFT_FORWARD` | 固定向左转 90°，左脚在前 | 睁眼 | 20 秒 |
| 4 | `SEMI_TANDEM_RIGHT_FORWARD` | 保持向左转 90°，右脚在前 | 睁眼 | 20 秒 |

有效采集总时长为 80 秒。姿势转换、说明、安全确认和稳定等待不计入 80 秒。

### 4.2 每阶段启动

1. 操作员示范并确认脚位；
2. 受试者完成站位；
3. 系统至少观察 3 秒稳定准备期；
4. 站位进入有效区域且受试者确认准备后开始 20 秒计时；
5. 操作员全程近距离保护，不主动触碰受试者；
6. 阶段结束后提示睁眼或换位，再进入下一阶段。

准备期数据可以保存用于内部质量诊断，但不进入正式 20 秒指标。

### 4.3 统一站位记录

每阶段保存：

- 标准坐标与上游适配器版本；
- 人体朝向：正向或固定左转 90°；
- 前脚：无、左、右；
- 足底接触掩码、足部角度、站距和相对位置；
- 操作员确认的姿势合规状态；
- 完成时间和终止原因。

板面坐标到身体 `AP/ML` 坐标的转换由硬件层完成。算法必须校验输入的 `coordinate_frame = SUBJECT_ML_AP`，并核对阶段记录中的 `FORWARD / LEFT_90` 和前脚信息；不能在算法内部根据设备行列号猜测方向。每个硬件适配器必须通过方向夹具和跨阵列契约测试后才能声明坐标有效。

## 5. 阶段完成状态

每个阶段只能进入以下一种业务状态：

| 状态 | 含义 | 风险解释 |
|---|---|---|
| `COMPLETED` | 按规定姿势完成 | 允许计算完整指标 |
| `BALANCE_FAILURE` | 因失稳、迈步、移动双脚、扶持或提前终止 | 是有效风险证据 |
| `SAFETY_ABORT` | 因头晕、近乎晕厥、胸部不适等停止 | 高风险背景/安全证据 |
| `NON_BALANCE_STOP` | 疼痛、听不懂指令、拒绝继续等 | 不自动判定平衡高风险 |
| `PROTOCOL_INVALID` | 姿势错误、闭眼阶段睁眼且无法纠正等 | 原则上重试该阶段 |
| `TECHNICAL_INVALID` | 设备、采集或数据质量失败 | 不能据此判断受试者风险 |

必须记录：

- 实际完成秒数；
- 迈步次数；
- 是否移动脚位；
- 是否触碰扶手；
- 是否由工作人员实际扶持；
- 是否出现明显近乎跌倒；
- 闭眼阶段是否睁眼；
- 终止原因枚举。

`BALANCE_FAILURE` 产生的部分数据保留。完成时间本身就是结果，不能因不足 20 秒而删除该阶段。

## 6. 数据质量门控

### 6.1 客户不可见的内部检查

- 原始分段和清单完整；
- 实际时长和帧数足够；
- 标准输入时间严格递增；
- 实际采样率和帧间隔满足指标能力描述符；
- 接触载荷、有效点、零值、饱和、坏点和边缘接触在允许范围内；
- 身体坐标、人体方向和前脚信息完整；
- 标准输入、测量一致性、参考人群、特征管线和规则版本可追溯。

V1 物理指标的初始工程门槛：

- `COMPLETED` 阶段有效时长不少于 19.0 秒；
- 实际中位采样率不少于 18 Hz；
- 不跨越大于两个名义帧间隔的缺口进行轨迹插值；
- 正式分析区间有效帧比例不少于按实际中位采样间隔估计帧数的 95%；
- 站位掩码不能持续接触测量有效区域边界；
- 零载荷或分母过小的帧不计算中心位置。

这些是版本化工程门槛，不是医学结论；上线前必须用标准物理 fixture、目标硬件和重复采集验证，并只能通过新版本调整。

### 6.2 质量结论

```text
VALID / DEGRADED / INVALID
```

- `VALID`：允许生成正式分项和综合结果；
- `DEGRADED`：只允许输出能力描述符明确批准的结果；
- `INVALID`：不输出由该数据计算的压力指标。

内部采样率、帧错误、质量分数和调试原因不得进入客户报告。

## 7. 数据预处理

设标准输入中的有效感应点为 `k`，法向力为 `F_k(t)`，身体坐标为 `ML_k, AP_k`：

```text
F_total(t) = Σ F_k(t)
ML(t)      = Σ(F_k(t) × ML_k) / F_total(t)
AP(t)      = Σ(F_k(t) × AP_k) / F_total(t)
```

`ML/AP` 的单位为 mm。只有 `physical_validation / timing_validation / coordinate_validation` 均通过且总力高于有效载荷门槛的帧，才进入正式压力中心轨迹。

处理顺序：

1. 校验 `physical-pressure-session/1.0` 模式、单位、身体坐标和版本；
2. 校验阶段边界、完成状态、质量标志和严格递增时间轴；
3. 排除上游标记为无效的点和帧，不在算法内重新解释设备错误；
4. 按真实法向力与物理坐标计算 ML/AP 压力中心；
5. 对压力中心轨迹使用版本化的轻量去毛刺和低通处理；
6. 不跨越超出能力门槛的时间缺口插值；
7. 从正式 20 秒区间计算指标。

滤波参数属于特征管线版本的一部分。V1 不用滤波弥补缺帧，不使用会改变事件峰值的强平滑。设备字节解析、零点、增益、坏点修复、阵列几何和坐标旋转不属于本特征管线。

## 8. 核心指标

### 8.1 每阶段指标

| 指标 ID | 定义 | 方向 |
|---|---|---|
| `completion_time_s` | 实际维持规定姿势的时间 | 越短越值得关注 |
| `cop_path_mm` | ML/AP 压力中心轨迹累计长度，mm | 越大越值得关注 |
| `mean_velocity_mm_s` | 轨迹长度 / 实际有效时长，mm/s | 越大越值得关注 |
| `ap_mean_velocity_mm_s` | AP 方向累计绝对位移 / 实际有效时长，mm/s | 越大越值得关注 |
| `ml_mean_velocity_mm_s` | ML 方向累计绝对位移 / 实际有效时长，mm/s | 越大越值得关注 |
| `ap_rms_mm` | AP 位移相对中心的 RMS，mm | 越大越值得关注 |
| `ml_rms_mm` | ML 位移相对中心的 RMS，mm | 越大越值得关注 |
| `ap_range_90_mm` | AP 的 P95−P5 稳健范围，mm | 越大越值得关注 |
| `ml_range_90_mm` | ML 的 P95−P5 稳健范围，mm | 越大越值得关注 |
| `ellipse_area_95_mm2` | AP/ML 协方差得到的 95% 椭圆面积，mm² | 越大越值得关注 |
| `total_force_cv` | 总法向力的变异系数 | 辅助识别动作和接触变化 |
| `contact_area_variation_mm2` | 有效接触面积变化，mm² | 辅助识别抬脚和站位变化 |

路径长度必须使用实际时间顺序。椭圆面积、RMS 和范围必须以人体 AP/ML 坐标计算。

### 8.2 闭眼变化

对轨迹速度、AP/ML RMS、稳健范围和椭圆面积计算：

```text
eyes_closed_ratio = EC / max(EO, epsilon)
eyes_closed_change = (EC - EO) / max(EO, epsilon)
```

闭眼变化用于“视觉依赖/感觉整合提示”，不能诊断前庭疾病。由于系统综述未证明闭眼一定带来额外跌倒预测增益，V1 不赋予预设固定权重。

### 8.3 半串联挑战

分别计算左脚在前和右脚在前相对双足睁眼的变化：

```text
semi_tandem_ratio_left  = ST_LEFT / max(EO, epsilon)
semi_tandem_ratio_right = ST_RIGHT / max(EO, epsilon)
semi_tandem_worse       = max(ST_LEFT, ST_RIGHT)
```

主要关注 ML RMS、ML 稳健范围、轨迹速度、椭圆面积和完成时间。

### 8.4 左右脚在前差异

对主要半串联指标计算对称差异率：

```text
side_difference = abs(ST_LEFT - ST_RIGHT)
                  / max((abs(ST_LEFT) + abs(ST_RIGHT)) / 2, epsilon)
```

左右差异进入 V1 评分，但必须同时满足：

1. 差异超过同一测量一致性规范的重复误差；
2. 差异超过冻结参考人群中的预设分位阈值；
3. 两个阶段均为有效或具有可解释的平衡失败记录。

轻微自然差异不扣分。左右差异用于筛查提示，不直接诊断单侧神经、关节或感觉疾病。

### 8.5 V1 不计算的指标

- 步态周期、步频、双支撑时间等动态步态指标；
- 依赖高采样率的冲击峰和快速事件；
- 频谱分区、熵、分形、DFA 和长时非线性指标；
- 上游未通过物理、时间或坐标验证的数据产生的任何正式物理指标；
- 疾病概率或特定疾病诊断。

## 9. 参考范围与指标分级

### 9.1 冻结参考人群

V1 正式输出 0–100 分前，必须建立符合标准物理输入与测量一致性规范的冻结参考工件：

```text
reference_population_id
input_schema_version
measurement_conformance_version
uncertainty_profile_version
test_protocol_version
feature_pipeline_version
age_band
sample_inclusion_rules
metric_distributions
repeatability_limits
artifact_sha256
approved_at
```

年龄层优先使用 `60–69 / 70–79 / >=80`。当某年龄层样本不足以形成稳定分布时，使用经批准的 60 岁以上合并参考，并在算法证据中记录降级，不动态使用正在增长的线上数据改变阈值。

### 9.2 分位分级

对“越大越异常”的指标，采用冻结参考分布：

| 参考分位 | 指标等级 |
|---:|---|
| `<= P75` | 正常范围 |
| `P75–P90` | 轻度异常 |
| `P90–P97.5` | 中度异常 |
| `> P97.5` | 明显异常 |

这些分位是 V1 的统计筛查规则，不是医疗临界值。完成失败和临床高风险背景不依赖分位阈值。

### 9.3 连续指标分数

每个指标按其冻结参考百分位映射为 0–100 的表现分：

- `P <= 50`：90–100；
- `P50–P75`：80–89；
- `P75–P90`：60–79；
- `P90–P97.5`：30–59；
- `P97.5–P100`：0–29。

区间内线性映射。方向相反的指标先转换为“异常百分位”。该映射使连续指标可用于区间内细分，但不会绕过后续风险规则。

### 9.4 领域分级

四个压力领域：

1. 基础摆动；
2. 闭眼变化；
3. 半串联挑战；
4. 左右脚在前差异。

每个领域使用 2–4 个预先批准的主要指标：

- 任一主要指标明显异常，或两个及以上中度异常：领域为明显异常；
- 任一中度异常，或两个及以上轻度异常：领域为中度异常；
- 只有一个轻度异常：领域为轻度异常；
- 其余：领域为正常。

领域原始连续分数取主要指标分数的中位数。随后按领域分级约束到对应区间：

| 领域分级 | 领域分数区间 |
|---|---:|
| 正常 | 80–100 |
| 轻度异常 | 80–89 |
| 中度异常 | 60–79 |
| 明显异常 | 0–59 |

即先用规则确定领域分级，再把原始连续分数限制在该分级的区间内。领域分级规则具有优先级，不能由多个正常指标平均掉一个已经满足的中度或明显异常规则。领域分数属于算法内部量，不作为第二个“总分”展示给客户。

## 10. 三路风险分级

### 10.1 背景风险等级

**明确高风险背景**，满足任一项：

- 过去 12 个月跌倒 `>=2` 次；
- 过去 12 个月任何跌倒造成受伤或需要就医；
- 跌倒后长时间无法自行起身；
- 意识丧失、晕厥或近乎晕厥；
- 反复头晕且影响站立/行走，或常在起身后出现。

**严重或多项高风险背景**：同时存在两个及以上明确高风险背景，或出现需要当日立即停止测试的安全症状。

**一般背景风险**，但未达到明确高风险：

- 过去 12 个月一次未受伤、未就医的跌倒；
- 感觉站立或行走不稳；
- 担心跌倒；
- 使用/被建议使用助行器或经常扶家具；
- 偶发轻度头晕但不影响站立/行走；
- 可选药物风险标签按 3.2 节规则命中。

### 10.2 动作完成等级

| 完成情况 | 等级 |
|---|---|
| 四项均完成，无扶持和近乎跌倒 | 正常 |
| 仅一个半串联因平衡原因未完成，其他三项完成，且无扶持/近乎跌倒 | 至少中风险 |
| 两项及以上因平衡原因未完成 | 高风险 |
| 闭眼和任一半串联均无法完成 | 高风险 |
| 左右两个半串联均无法完成 | 高风险 |
| 双足睁眼无法安全完成 | 高风险 |
| 工作人员实际扶持或出现明显近乎跌倒 | 高风险 |

单个半串联未完成时，如果同时存在扶持、近乎跌倒或其他明显异常，升级为高风险。

### 10.3 压力指标等级

- **表现良好**：没有中度/明显异常，最多一个轻度异常；
- **需要关注**：一个领域中度异常，或多个领域轻度异常；
- **表现较差**：任一领域明显异常，或两个及以上领域中度异常。

左右脚在前差异按第 8.4 节进入领域分级。

## 11. 综合等级与 0–100 评分

### 11.1 先定等级

```text
综合风险等级 = max(
    背景风险等级,
    动作完成等级,
    压力指标等级
)
```

风险优先级为：`高风险 > 中风险 > 低风险`。任何高风险背景或高风险完成规则都不能被正常压力指标抵消。

### 11.2 分数上限

规则引擎为每路证据产生分数上限：

| 证据 | 上限 |
|---|---:|
| 无背景风险 | 100 |
| 一般背景风险 | 79 |
| 一个明确高风险背景 | 59 |
| 严重或多项高风险背景 | 39 |
| 四项动作完成 | 100 |
| 单个半串联平衡失败 | 79 |
| 两项及以上平衡失败、扶持或近乎跌倒 | 59 |
| 双足睁眼失败并需要保护，或多项严重完成失败 | 39 |

压力领域先按第 9 节形成连续表现分；压力表现候选分取四个领域中最低的可信领域分，避免明显薄弱环节被其他正常领域平均掉。随后根据 10.3 节已经确定的压力等级，再次约束候选分：

| 压力指标等级 | 压力候选分区间 |
|---|---:|
| 表现良好 | 80–100 |
| 需要关注 | 60–79 |
| 表现较差 | 0–59 |

因此连续分只负责同一等级区间内的排序，不负责推翻规则等级。

最终分数：

```text
raw_score = min(
    pressure_performance_candidate,
    background_score_cap,
    completion_score_cap
)

final_score = clamp_to_overall_risk_band(
    raw_score,
    overall_risk_tier
)
```

该公式只在综合等级已经由规则确定后用于区间内定位。最终结果必须再次断言：

```text
低风险  -> 80 <= final_score <= 100
中风险  -> 60 <= final_score <= 79
高风险  -> 0  <= final_score <= 59
```

压力指标因技术原因不可用时，不把缺失值当作 0 分，也不虚构压力候选分：

1. 如果背景或动作完成规则已经能独立确定中风险/高风险，计算 `raw_score` 时排除压力候选项，只使用实际成立的背景和完成上限；最终分数仍约束在已确定的综合等级区间内，报告必须标记“压力指标未评价”。
2. 如果背景和完成情况均不能独立建立风险等级，则返回“无法评价”，不生成数字。

同理，任何缺失领域都只能在其余可信领域足以完成压力分级时被排除；否则压力指标整体为“无法评价”。

### 11.3 典型组合

| 背景 | 完成 | 压力指标 | 综合结果 |
|---|---|---|---|
| 明确高风险 | 完成 | 良好 | 高风险，最高 59；压力表现仅作辅助 |
| 无明显背景 | 多项无法完成 | 无完整指标 | 高风险；完成失败本身是证据 |
| 无明显背景 | 完成 | 表现较差 | 高风险，0–59 |
| 一般背景 | 完成 | 良好 | 中风险，最高 79 |
| 无明显背景 | 单个半串联失败 | 其余良好 | 中风险；伴扶持/近乎跌倒则高风险 |
| 无明显背景 | 完成 | 需要关注 | 中风险，60–79 |
| 无明显背景 | 完成 | 良好 | 低风险，80–100 |
| 无高风险背景 | 技术无效 | 不可用 | 无法评价，建议重测 |

## 12. 报告结构

客户报告只突出一个 0–100“综合筛查评分”，不再突出第二个可能与综合风险矛盾的压力板总分。压力板结果以分项形式呈现。

### 12.1 第一部分：筛查摘要

- 综合筛查评分；
- 低/中/高风险提示；
- 一句话主要依据；
- 下一步建议；
- 非诊断声明。

示例：

> 综合筛查提示为高风险。受试者报告过去 12 个月反复跌倒；本次静态平衡测试表现尚可，但不能抵消既往跌倒所提示的日常风险。建议到医院或专业机构进一步评估。

### 12.2 第二部分：风险依据

- 明确高风险背景，只显示经过受试者/操作员确认的通俗标签；
- 一般背景因素；
- 四阶段完成情况、实际完成时间和是否迈步/扶持；
- 影响最终等级的主要压力领域。

药物只显示类别标签，不显示药名。未知、拒绝和未采集不显示为阴性结论。

### 12.3 第三部分：平衡测试分项

- 基础静态稳定性；
- 闭眼变化；
- 半串联窄基底控制；
- 左右脚在前差异；
- 四阶段身体 ML/AP 压力中心轨迹图；
- 经批准的核心指标和通俗解释；
- 必要时显示“未完成/未评价”，不以 0 伪装缺失。

### 12.4 第四部分：图表和方法

- 四阶段热力图或代表帧；
- 人体 AP/ML 方向的真实物理压力中心轨迹；
- 主要曲线；
- 协议、算法、参考人群和报告版本；
- 生成时间和报告 ID。

### 12.5 不得进入客户报告

- 帧校验、采样抖动、坏点比例和内部质量分；
- 原始协议未验证标记；
- 算法堆栈、调试参数、模型内部证据 JSON；
- 诊断包、队列状态、对象键和存储路径；
- 未经批准的实验指标；
- 身份明文、具体药名或敏感处方信息。

## 13. 可生成的结果

### 13.1 正式结果

- `overall_risk_level`: `LOW / MEDIUM / HIGH`；
- `overall_screening_score`: `0..100`；
- `result_status`: `COMPLETE / PARTIAL_HIGH_RISK / NOT_ASSESSABLE`；
- `background_risk_summary`；
- `completion_profile`；
- `balance_domain_results`；
- `key_findings`；
- `recommended_action`；
- `reportable_figures`；
- 算法、特征、参考范围和协议版本引用。

### 13.2 建议文案

| 结果 | 建议 |
|---|---|
| 低风险 | 保持日常活动和适宜的平衡/力量训练；出现跌倒或明显不稳时重新评估 |
| 中风险 | 建议关注相关因素，进行更完整的步态、力量或专业平衡评估 |
| 高风险 | 建议到医院或专业机构进一步评估；若伴晕厥、急性头晕或胸部不适，应及时就医 |
| 无法评价 | 排除设备/操作问题后重新测试；若因身体不适停止，按安全建议处理 |

系统不得自动诊断前庭疾病、神经系统疾病、周围神经病、帕金森病或骨关节疾病。

## 14. 云端分析、版本和重算

每次分析保存不可变 `AnalysisRun`：

```text
session_id
input_manifest_sha256
input_schema_version
measurement_conformance_version
uncertainty_profile_version
test_protocol_version
feature_pipeline_version
rule_set_version
reference_population_id
parameters_sha256
capability_status
result_schema_version
```

相同输入和相同版本幂等。参考范围、规则或特征管线发生变化时创建新的 `AnalysisRun`，不覆盖旧结果。新运行可以在同一 `report_id` 下生成新的 `CLOUD_COMPLETE` 报告版本和 PDF 工件。

云端必须从完整原始会话经版本固定的硬件适配器重建标准物理输入，再统一生成一级特征。客户端本地结果是短时断网兜底快照，不作为云端权威特征输入。

## 15. 验证与发布门槛

### 15.1 自动测试

- 标准物理 fixture 验证中心位置、轨迹长度、ML/AP 速度、RMS、范围和椭圆面积；
- 不同点数、点距和阵列形状表达同一物理场景时，核心特征在批准容差内一致；
- golden 会话验证指标和评分确定性；
- 高风险背景永远不能产生大于 59 的分数；
- 一般背景风险永远不能产生大于 79 的分数；
- 单个半串联平衡失败至少中风险；
- 多项平衡失败、扶持和近乎跌倒产生高风险；
- 技术无效不会误判为受试者高风险；
- 未提供药物标签不会被解释为“没有服用”；
- 上游提供统一身体坐标后，正站、左转和前脚交换不改变 ML/AP 轴语义；
- 相同输入和版本产生相同结果；
- 客户报告白名单不泄露内部质量和敏感信息。

### 15.2 硬件适配器与真机验证

- 每个适配器的已知载荷、物理坐标、方向和时间轴验证；
- 正站和左转 90°时输出始终使用统一身体 ML/AP 坐标；
- 空板、标准载荷和重复站立的稳定性；
- 20 秒指标在适配器声明采样能力下的重复性；
- 左右脚在前差异的测量最小可检测变化；
- 分段、断网、恢复和云端重建后标准物理输入及指标不变；
- 至少两种不同阵列布局的跨适配器一致性验证。

### 15.3 人工/临床验证

- 操作员能一致识别迈步、扶持、近乎跌倒和非平衡停止；
- 老年受试者能够安全理解四阶段指令；
- PDF/打印中的风险文案不会被误解为诊断；
- 建立 60 岁以上参考样本和年龄层分布；
- 记录未来 12 个月跌倒结局，验证区分度、校准度、敏感度、特异度和偏差；
- 根据前瞻性数据训练或调整真实模型权重和阈值。

自动测试通过不代表真机、参考范围或临床验证完成。在上述门槛未完成时，结果必须标记为 V1 初步筛查规则，不能声称医疗级跌倒预测。

## 16. 已明确排除的设计

- 不使用 `25% / 25% / 40% / 10%` 等未经临床验证的固定权重；
- 不让一次正常压力板表现抵消明确高风险背景；
- 不把受试者无法完成当作普通缺失数据；
- 不把设备失败当作受试者平衡失败；
- 不采集具体药名和处方文本；
- 不将左右脚轻微自然差异解释为疾病；
- 不使用线上滚动样本静默改变已经发布的参考阈值；
- 不在客户报告中展示内部质量和调试信息。
