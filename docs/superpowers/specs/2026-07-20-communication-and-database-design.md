# 通信接口与数据库设计 —— 已批准设计规范

## 1. 目的

本规范记录 2026-07-20 已确认的通信接口和数据库设计边界，作为正式文档与后续实施计划的决策依据。

## 2. 已确认范围

通信接口覆盖：

1. DO-P4864 串口协议；
2. 机构采集端与云端 REST/分段上传接口；
3. 云端异步事件和模块内部契约；
4. 终端激活、心跳、License、配置、日志和报告接口。

数据库设计覆盖：

1. 客户端 SQLite；
2. 云端 PostgreSQL；
3. S3 兼容对象存储的路径、摘要、版本和生命周期。

医院 HIS、LIS、EMR、体检系统及受试者公开接口不在本期范围。

## 3. 方案选择

采用“契约优先的模块化单体”：

- 首版云端可部署为一个 FastAPI 应用；
- 外部接口使用版本化 REST/OpenAPI；
- 云端内部使用事务 Outbox 和版本化事件；
- 模块不得直接修改其他模块的私有表；
- 当吞吐、团队和运维边界明确后，再按当前契约拆服务。

未采用从第一版开始微服务，原因是部署、消息一致性和运维成本超过当前阶段需要；未采用无边界单体，原因是会导致上传、分析、报告和设备管理耦合。

## 4. 通信设计决策

- HTTP API 使用 `/v1`、TLS、短期终端凭据和统一关联 ID。
- 所有创建和状态变更请求具有幂等键与请求摘要。
- 原始数据按不可变业务分段上传；相同索引相同摘要幂等，相同索引不同摘要冲突。
- 采集线程不等待 HTTP、算法或报告。
- 会话最终清单验证完成后才发布 `session.ingested.v1`。
- 云端内部事件至少一次投递，消费者必须去重。
- 错误响应同时提供 HTTP 状态、稳定错误编号、是否可重试和建议动作。
- 终端心跳不得包含受试者身份明文、原始压力或报告内容。
- 报告下载使用短期受控地址，不产生永久公开 URL。

DO-P4864 基线：

- 48×64，共 3072 点；
- 1,000,000 baud、约 12 Hz；
- 6151 bytes/帧；
- 小端 uint16 承载 12-bit 数据；
- 单字节补码 CheckSum；
- 无设备帧序号和设备时间戳。

设备手册没有明确 CheckSum 调用范围，因此必须由 P0 真机 fixture 确认后固化为协议配置版本，不得猜测。

## 5. 数据库设计决策

### 5.1 客户端

- SQLite WAL 保存终端、受试者缓存、授权、会话、分段、上传任务和报告状态。
- 原始分段保存在加密不可变文件中，不保存为 SQLite BLOB。
- 只有 `SEALED` 分段可以上传。
- 服务端确认前不得按正常策略删除本地分段。
- 测试有效性、上传、分析和报告分别保存状态。
- 基础报告和云端完整报告共享 `report_id`，版本不可变。

### 5.2 云端

PostgreSQL 按 `iam/device/subject/screening/analysis/reporting/ops` schema 分区。所有租户业务表包含 `tenant_id`，生产环境使用 RLS 作为纵深防御。

- 身份字段应用层信封加密；
- 外部编号用受控 HMAC 做机构范围精确查询；
- 算法角色不能访问身份保险库；
- 原始矩阵、特征大数组、PDF 和诊断包进入对象存储；
- PostgreSQL 只保存关系、状态、摘要、版本和对象键；
- 状态更新和 Outbox 事件在同一事务提交；
- 新算法和新报告产生新版本，不覆盖历史。

### 5.3 对象存储

对象键只使用租户和内部 UUID，不包含姓名、联系方式、档案号或病历号。最终对象不可覆盖；同键同摘要幂等，同键不同摘要进入冲突。生命周期由版本化保留策略驱动。

## 6. 一致性不变量

1. 未可靠落盘的数据不能只存在于上传内存队列。
2. 未确认的分段不能正常删除。
3. 未通过完整清单验证的会话不能启动正式云端分析。
4. 未通过能力和质量门控的指标不能进入客户报告。
5. 受试者、授权、终端和设备引用必须与认证租户一致。
6. 相同输入和相同版本的分析任务只产生一个业务结果。
7. 已交付报告版本不能静默改写。
8. 日志和对象路径不得绕过身份数据分区。
