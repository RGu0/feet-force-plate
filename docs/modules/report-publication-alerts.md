# 云端报告发布告警

FeetForcePlate 的普通报告和静态平衡报告在创建新的 `CLOUD_COMPLETE` 版本时启用以下规则。产品定义复用 Foundation 0.9.4 的告警评估器。两种报告在同一进程共享默认监控器，按机构独立评估。

| 规则 | 触发与恢复 | 值班处理 |
|---|---|---|
| `ffp-pdf-render-failed-v1` | PDF 渲染器抛出异常即告警；同机构后续一次成功渲染恢复。构建文档、工件写入和发布事件的异常分别沿原路径上抛。 | 查渲染器、字体及模板版本，用合成报告复测。核对后续成功渲染和恢复记录。 |
| `ffp-report-publication-delayed-v1` | 默认 300 秒。时钟从报告进入版本发布函数起，覆盖存储、渲染与发布事件；仓库确认需要新建版本后启动计时器。执行仍阻塞时即可告警。一次按时发布成功且同机构没有仍在执行的超时发布时恢复。 | 核对报告工作进程、工件存储与发布事件的可用性。确认同一机构恢复正常发布。上游分析积压需查分析队列指标。 |

300 秒是可配置的软件初值，运维可在构建两个报告服务时传入同一个 `ReportPublicationAlerts(delay_seconds=...)`。目标环境的阈值和投递渠道由监控演练验证。相同机构、相同规则的持续告警按 15 分钟冷却去重；达到冷却时间后的下一次越界观测可发提醒。已发布版本的幂等重放和被行政冻结的请求不产生样本。

默认输出到 `cloud.reporting.alerts` 日志，OPEN 为 WARNING，RESOLVED 为 INFO。日志只含规则、状态、事件编号、机构标识摘要、次数和本处理指引。可传入 Foundation `MetricsSink` 导出数值观测：`ffp_pdf_render_failed_v1` 成功为 0、失败为 1；`ffp_cloud_complete_publication_seconds_v1` 为成功发布耗时。告警状态按进程保存。目标环境的日志收集、通知及操作员演练归 RAY-517 V3。
