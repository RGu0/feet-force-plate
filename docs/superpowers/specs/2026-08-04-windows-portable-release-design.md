# Windows 便携版发布设计

## 目标与范围

首个客户交付采用 Windows x86_64 便携 ZIP，而不是安装器。交付物必须是
可复现的 PyInstaller `onedir` 应用目录、其 ZIP 压缩包、SHA-256 摘要和发布
清单。该流程为后续 Inno Setup 安装器保留同一应用目录输入。

本设计只覆盖仓库内可自动化的发布准备。代码签名证书、生产 API 地址、
License 公钥、支持诊断接收方公钥、云端放行和真机现场验收是受控外部输入，
不写入仓库也不得通过脚本绕过。

## 发布目录与构建行为

`scripts/build-portable-release.ps1` 从锁定依赖构建 PyInstaller 应用，默认要求：

1. 运行 Windows Authenticode 签名工具并验证应用 EXE 签名；
2. 运行发布校验脚本；
3. 创建 `FeetForcePlate-<version>-windows-x86_64.zip`、同名 `.sha256` 与
   `release-manifest.json`。

签名材料只从运行环境取得（证书指纹与签名工具路径）。缺少材料时默认失败。
开发人员可以显式选择未签名开发构建；其名称和清单必须标记为 `unsigned-development`，
校验脚本拒绝把它作为可交付发布包。

PyInstaller 需要随包带入：

- `client/app/assets`；
- DO-P4864 设备规格 JSON；
- 构建时提供的支持诊断公钥（如有）。

产品代码只从包内位置加载这些资源，不能要求客户电脑含有仓库的 `docs/` 目录。

## 发布清单与校验

`release-manifest.json` 是 UTF-8 JSON，至少记录：应用版本、目标平台、构建
时间、构建提交标识、签名状态、ZIP 文件名、ZIP SHA-256，以及应用 EXE 相对路径。
发布校验脚本验证：清单架构、摘要、资源存在、EXE 的 Authenticode 签名和未签名
开发包禁止交付。签名状态不能由调用者手工伪造。

## 用户与运维交付材料

仓库提供两份中文文档：

- 用户安装与启动说明：解压、运行、CH340 驱动的确认安装、首次联网要求、卸载/删除
  数据的区别、常见故障和发布时必须填入的支持联系渠道；
- 发布放行清单：证书、哈希、License/云端配置、诊断公钥、真实设备、打印/PDF、
  升级/回退、隐私与现场负责人逐项签字确认。

文档不得嵌入任何生产地址、凭据、私钥或真实受试者数据。
发布负责人不得在支持联系渠道为空时交付 ZIP。

## 故障处理与安全边界

- 缺少设备规格、资源、签名、哈希或外部受控输入时构建/校验必须非零退出；
- 驱动不由 ZIP 静默安装，应用继续在启动检测中给出用户可理解的提示；
- ZIP 解压目录不保存客户数据；运行时数据仍由应用放在平台数据目录；
- 未签名开发包仅用于内部测试，不能发送给客户。

## 测试与验收

先为冻结包资源、发布清单和发布校验编写失败测试。自动验证包含相关单元测试、
完整 pytest 回归、未签名开发构建、以及签名发布构建所需输入缺失时的失败行为。
真正的签名验证、机构登录、License、CH340 真机采集、打印和现场网络验收必须在
持证书和目标设备的发布环境中记录。
